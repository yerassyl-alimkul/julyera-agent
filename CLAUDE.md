# JulYera Agent: контекст проекта

Личный ИИ-агент для управления задачами на нескольких человек (Yera и допущенные им люди, сейчас жена).
У каждого свои задачи, заметки, подзадачи, Telegram-чат и Google Calendar; вход через Telegram (см. «Модель доступа»).
Пользователь пишет или наговаривает задачу, Groq превращает текст в структурированную задачу,
она сохраняется в Supabase и показывается в Telegram-боте, веб-интерфейсе и Google Calendar.

Файл написан по памяти из длинного чата и мог устареть. Если он расходится с кодом, верь коду
и поправь этот файл.

## Как работать с владельцем

- Отвечай по-русски.
- Владелец хорошо понимает продукт, но терминал, git и инфраструктуру знает слабо.
  Перед командами коротко объясняй, что они делают, и не склеивай несколько команд в одну строку.
- Каждый `git push` в `main` сразу деплоится в прод (Render). Перед пушем спрашивай подтверждение.
- Никогда не выводи и не коммить значения ключей и содержимое `.env`.
  Если секрет попал в чат или лог, скажи, что его надо перевыпустить.

## Стек

- Backend: Python 3.12, FastAPI + uvicorn (`main.py`).
- База: Supabase (Postgres) через `supabase-py` с ключом `service_role` (RLS обходится).
- LLM: Groq. Разбор текста в задачи (модель задана константой `MODEL` в `groq_client.py`),
  голосовые сообщения распознаёт `whisper-large-v3`.
- Клиенты: Telegram-бот, веб-интерфейс `web/index.html` (чистый JS, без сборки).
- Хостинг: Render, бесплатный Web Service, адрес `https://julyera-agent.onrender.com`
  (он же зашит в `reminders.yml` и как запасной `BASE_URL` в `web/index.html`).
  После простоя засыпает, холодный старт до ~50 секунд.
  Версия Python закреплена переменной `PYTHON_VERSION=3.12.7` в Render (`runtime.txt` Render игнорирует, поэтому его в репозитории нет).
- Расписание: GitHub Actions (`.github/workflows/reminders.yml`).
- Календарь: Google Calendar API (OAuth, scope `calendar.events`).

## Структура

- `main.py`: все HTTP-маршруты, зависимость входа `current_user`, webhook Telegram, раздача статики.
- `telegram_auth.py`: проверка подписи initData Telegram Mini App. `users_service.py`: пользователи и их чаты.
- `task_service.py`: логика задач (создание, обновление, повторяющиеся, напоминания, синхронизация с календарём).
- `notes_service.py`, `subtasks_service.py`: CRUD заметок и подзадач. `categories_service.py`: свои категории пользователя.
- `google_calendar_service.py`: OAuth и события календаря.
- `groq_client.py`: промпт `SYSTEM_PROMPT`, разбор текста, распознавание голоса.
- `telegram_handlers.py`: обработчики бота (`/start`, `/list`, текст, голос), общие для polling и webhook.
- `bot.py`: локальный запуск бота в режиме polling.
- `models.py`: Pydantic-модели. `database.py`: клиент Supabase.
- `schema.sql`: журнал миграций (не скрипт для повторного запуска). Новые миграции дополнительно отдельными
  файлами `migrations/NNN_name.sql`; изменения схемы только добавляющие, SQL выполняет владелец.
- `web/index.html`: весь фронтенд в одном файле (светлый мобильный дизайн, см. ниже «Фронтенд»).
- `scripts/isolation_check.py`: проверка изоляции данных между пользователями (+ `scripts/fake_supabase.py`, база в памяти).
- `design/`: спецификация нового дизайна `DESIGN.md` (раздел 12 — решения владельца), макеты `reference/*.dc.html`,
  тестовый сервер `mock_server.py` с подставными данными.

Маршруты: `/tasks` (+ `/tasks/parse`, `/tasks/{id}`), `/notes`, `/subtasks`, `/tasks/{id}/subtasks`,
`/google/auth-url|auth|callback|status`, `/telegram/webhook/{token}`, `/internal/reminders/run`, `/health`.
Публичные только `/health`, статика, `/google/callback` (защищён подписанным `state`), `/telegram/webhook/{token}`
(защищён токеном в адресе) и `/internal/reminders/run` (заголовок `X-Reminder-Secret`); остальное требует входа.

## Переменные окружения (только имена)

`SUPABASE_URL`, `SUPABASE_KEY` (service_role), `GROQ_API_KEY`, `TELEGRAM_BOT_TOKEN`,
`WEBHOOK_BASE_URL` (только прод), `REMINDERS_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
`GOOGLE_REDIRECT_URI`, `OAUTH_STATE_SECRET` (подпись `state` при подключении календаря, случайная строка от 32 символов;
задаёт владелец на Render, в репозиторий не попадает), `PYTHON_VERSION` (только Render).
Шаблон с комментариями: `.env.example`.
В GitHub Actions секрет называется `REMINDER_SECRET` (без S) и должен совпадать с `REMINDERS_SECRET` на Render.

## База данных

- `users`: `id`, `name`, `telegram_user_id` (уникальный), `is_admin`, `access_key` (для ссылки `/web`).
  У `tasks`, `notes`, `telegram_chats` есть `user_id`; у `google_credentials` первичный ключ `user_id`
  (раньше одна строка `id = 1`). Миграция записана в конце `schema.sql`.
- `categories`: `user_id`, `name`, `color` (из палитры `categories_service.PALETTE`), `sort_order`; уникальность
  `(user_id, lower(name))`. Переименование — SQL-функция `rename_category` (меняет и задачи), вызывать её может
  только `service_role`.
- `tasks`: `task`, `category` (название категории пользователя текстом, без CHECK), `source`, `deadline` (timestamptz), `priority` (High | Mid | Low),
  `status` (To Do | In Progress | Done), `note`, `is_recurring`, `recurrence_pattern`, `tags` (text[]), `google_event_id`.
- `subtasks` (связь с `tasks` каскадом, своей колонки `user_id` нет), `notes`, `telegram_chats` (для напоминаний),
  `google_credentials` (по строке на пользователя).
- Миграции выполняются вручную в Supabase SQL Editor. Перед новой миграцией спроси владельца, что уже применено.
- В интерфейсе статус `In Progress` не используется: все не-Done задачи показываются вместе как «To Do», Done уходит в «Архив».

## Модель доступа (несколько пользователей)

- Backend ходит в базу с ключом `service_role`, который обходит RLS. Вся изоляция держится на условии `user_id`
  в каждом запросе к `tasks`, `notes`, `telegram_chats`, `google_credentials`; подзадачи проверяются через их задачу
  (`subtasks_service._owns_task`). Новый запрос без такого условия — дыра. Чужой `id` в маршруте даёт 404.
- `user_id` всегда ставит сервер из `current_user`; модели создания и обновления его не содержат, лишние поля
  от клиента игнорируются.
- Вход: заголовок `X-Telegram-Init-Data` (Mini App; подпись проверяется токеном бота, срок 24 часа) или
  `X-Access-Key` (ссылка `/web` для браузера). Нет входа или подпись неверна → 401; человек не допущен → 403
  `{"code": "not_approved"}`.
- Новых людей допускает владелец (`is_admin`): незнакомец пишет боту `/start`, владельцу приходит запрос с кнопками
  «Разрешить» / «Отклонить». Решение принимается по `from.id` нажавшего, повтор не дублирует пользователя,
  запрос не чаще раза в час (счётчик в памяти). Неизвестный чат ничего не создаёт.
- Google Calendar у каждого свой: токены по `user_id`, в `state` подписанная метка `user_id` на 10 минут
  (`make_state` / `verify_state`). Фронтенд берёт адрес через `/google/auth-url` и открывает его во внешнем браузере.
- Честный статус: `/google/status` → `{configured, connected, needs_reconnect}`; токен проверяется вживую
  (обновление access-токена), результат кэшируется на 10 минут. `invalid_grant` (RefreshError) и 401/403 от API
  ставят `google_credentials.needs_reconnect`, бот один раз пишет «переподключите», синхронизация пропускается;
  сеть, 5xx и 404 — временные сбои, только лог. Успешный callback снимает флаг. Задач до подключения не догоняем.
- Напоминания идут каждому пользователю в его чаты и только с его задачами.
- Категории у каждого свои: название 1–30 символов, уникально без учёта регистра; цвет только из палитры (8 цветов);
  хотя бы одна категория всегда есть (новому при одобрении — «Общее»), первая по порядку — запасная для парсера.
  `POST/PATCH /tasks` с чужой или несуществующей категорией → 422; удаление категории с задачами требует `move_to`
  (иначе 409). Парсер получает названия категорий пользователя, неизвестный ответ модели заменяется запасной.

## Договорённости, которые нельзя ломать

1. **Время дедлайна хранится «голыми часами» без часового пояса.** Supabase отдаёт его с суффиксом `+00:00`,
   но это ложная метка. В Python перед передачей наружу снимай tzinfo (`replace(tzinfo=None)`; сейчас это делает только
   `_event_body` в `google_calendar_service.py`, остальной код берёт `.date()`/`strftime` и от метки не зависит),
   во фронтенде разбирай строку через `parseNaiveDeadline`. Не используй `new Date(isoString)` для показа времени,
   иначе время сдвинется на часовой пояс браузера.
2. **Часовой пояс пользователя** — колонка `users.timezone` (по умолчанию `Europe/Rome`, редактирования в интерфейсе нет),
   читается через `users_service.timezone_of`. По нему ставятся события Google Calendar (`_event_body`) и считается
   «сегодня» при разборе текста (`parse_text_to_tasks(..., timezone=...)`). Родной часовой пояс владельца Asia/Almaty.
   Расписание напоминаний посчитано по Алматы: cron 04:00 / 11:00 / 16:00 UTC = 09:00 / 16:00 / 21:00.
3. **Статика монтируется на `/` самой последней** в `main.py`, иначе она перекроет API-маршруты.
4. **Polling и webhook у одного бота несовместимы.** Запуск `bot.py` локально снимает webhook у прод-бота.
   Пока работает прод, локально бота не запускай. Webhook возвращается при перезапуске сервиса на Render.
5. **Имена моделей Groq меняются.** Если Groq вернёт `model_not_found`, смени `MODEL` в `groq_client.py`.
6. Повторяющаяся задача при переводе в Done создаёт следующую (+1 день, +1 неделя или +30 дней).
   Копия переносит теги и сразу получает своё событие в Google Calendar (`update_task` в `task_service.py`).
   Подзадачи не копируются.
7. Синхронизация с Google Calendar односторонняя (задачи → события). Событие удаляется при Done,
   при удалении задачи и при снятии дедлайна. Любые ошибки календаря (не только `HttpError`: сеть, тайм-аут,
   отозванный токен) логируются и не ломают работу с задачами. В `Credentials` обязательно передаётся `expiry`,
   иначе протухший токен обнаруживается только посреди запроса.
   `PATCH /tasks/{id}` обновляет только переданные поля; явный `null` принимается лишь для
   `deadline`, `note`, `source`, `recurrence_pattern` (`NULLABLE_FIELDS` в `task_service.py`), так снимается дедлайн.
8. Теги берутся из текста только как явные хэштеги, остальное модель выдумывать не должна.
9. Напоминания (`get_reminder_tasks`) берут не-Done задачи с дедлайном до «сегодня + 2 дня» включительно,
   сравнивая только даты. «Сегодня» считается по часам сервера Render (UTC), а не по Алматы.
   Telegram-команда `/list` показывает только статус `To Do`, без `In Progress`.

## Фронтенд (`web/index.html`)

- Дизайн по `design/DESIGN.md`, шрифты Onest и Unbounded. Цвета, отступы, радиусы
  и длительности анимаций берутся только из CSS-переменных в `:root`, голых значений не добавляй.
- Две темы. Тёмная — переопределение токенов в `:root[data-theme="dark"]`; атрибут ставит скрипт в `<head>`
  до отрисовки (`resolveTheme`/`applyTheme`). «Авто» повторяет `Telegram.WebApp.colorScheme` в Mini App
  (событие `themeChanged`) или `prefers-color-scheme`; выбор «Авто / Светлая / Тёмная» в меню хранится в `localStorage`.
  Цветные карточки задач в тёмной теме остаются пастельными: внутри них токены возвращаются к светлым (правило
  `:is(.task-row, .archive-row, .compact-row, .search-row)`). Заливка `--ink` с текстом поверх — пиши текст
  через `--on-ink`, а не `#FFFFFF`; акцентный текст — `--accent-text`; новые цвета добавляй в обе темы.
- Знак JulYera (буква «J» и галочка-«Y») — исходники в `design/brand/`. В интерфейсе он встроенный SVG
  `.brand-mark` с цветами `--logo-j`/`--logo-y` (меняются с темой): в меню и на экране входа.
  Иконки `web/apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` и аватар бота
  `design/brand/julyera-bot-avatar.png` рисует скрипт из SVG (Pillow); `web/favicon.svg` — копия `julyera-app-icon.svg`.
  Аватар бота ставит владелец в BotFather (`/setuserpic`), из кода его не поменять.
- Одна колонка: на телефоне во всю ширину, на ноутбуке 480 px по центру. Нижняя панель «Задачи / Календарь /
  Заметки» и кнопка «+». Меню — шторка слева на любой ширине.
- Экраны: главная (полоса дней «Просрочено», «Без даты», 14 дней вперёд и дальше дни с задачами), архив,
  календарь, заметки; модальные `sheet`: «Новая задача», «Изменить», «Фильтры», «Поиск».
- «Все задачи»: кнопка `layoutBtn` в шапке переключает «Задачи» между видом по дням и всеми активными задачами
  разделами по датам (`listLayout`, `renderAll`; выбор запоминается в `localStorage`). Перерисовку списка
  вызывай через `renderTaskList()`, а не `renderMain()` напрямую.
- «Новая задача» в двух режимах: «ИИ» (`POST /tasks/parse`) и «Вручную» (`POST /tasks` с категорией, приоритетом,
  дедлайном и тегами из формы). Последний режим запоминается. Чипы категории и приоритета общие с «Изменить»
  (`renderCategoryPriorityChips`).
- Опрос `loadTasks` раз в 15 секунд. Пока открыт свайп или идёт ввод шага в раскрытой карточке, перерисовка
  откладывается (`isRowInteractionBusy`, `flushDeferredRender`). Перерисовка пересоздаёт элементы, фокус
  возвращается по атрибуту `data-focus-key` — ставь его новым кнопкам в списках.
- Удаление задач и заметок идёт через `pendingDeletions` / `pendingNoteDeletions` (5 секунд на отмену);
  загрузки отфильтровывают ожидающие удаления, иначе они «воскресают».
- Пока открыт модальный экран или меню, фон получает `inert` (`setBackgroundInert`). Esc закрывает верхний слой.
- Поиск игнорирует фильтры (грузит все задачи в `searchPool`); задачу по id искать через `findTask`.
- Загрузка: `firstLoad()` сразу показывает заглушки и повторяет `GET /tasks` с паузой 2 → 4 → 8 → 15 с около минуты
  (холодный старт Render), без уведомлений; потом экран «Не удалось загрузить задачи» с кодом вида `GET /tasks → 502`
  и кнопкой «Повторить». Обязателен только `/tasks`, сбой `/subtasks` не мешает списку. Тайм-аут запроса 30 с,
  параллельные `loadTasks` не дублируются. Ошибки скрипта до загрузки ловят `error` / `unhandledrejection` и показывают
  тот же экран с кодом `JS: …`. Методы Telegram SDK вызываются с проверкой `isVersionAtLeast` и в `try`.
- Все запросы к серверу только через `api(path, options)`: она добавляет заголовок входа и показывает экран
  «Откройте приложение из Telegram» (401) или «Ждём одобрения владельца» (403); удачный запрос его убирает.
  Прямой `fetch(BASE_URL…)` не добавляй.
- Категории приходят из `GET /categories`; цвет строки задаётся переменной `--row-bg` (`paintRow`), цвет чипа —
  `--chip-color`. Классов по названиям категорий нет. Экран «Категории» в меню: цвет из палитры, название, порядок,
  добавление, удаление с выбором, куда перенести задачи.
- Telegram Mini App: `telegram-web-app.js`, `ready`/`expand`, цвета шапки и фона из `--bg`, `disableVerticalSwipes`.
  Отступы `--app-inset-top`/`--app-inset-bottom` берутся из `safeAreaInset` + `contentSafeAreaInset`, в браузере из `env()`.
  Внутри Telegram экспорт CSV и печать скрыты (подсказка про `/web`), микрофон скрыт, если нет Web Speech API.
  Ключ из `?key=` сохраняется в `localStorage` и остаётся в адресной строке (если его нет в адресе, но есть
  в памяти — возвращается туда). Это нужно для «На экран Домой»: у иконки на iPhone своя память, она открывает
  адрес, с которого её добавили. Поэтому в `web/manifest.json` нет `start_url`. Неверный ключ (401) убирается
  и из памяти, и из адреса.
- Все нажимаемые элементы не меньше 44 × 44 (исключение: клетки календаря на 360 px, 41 px в ширину).

## Ошибка загрузки Mini App 7 октября 2026 (диагностика)

Симптом: в Mini App на iPhone в 12:03 по Риму (10:03 UTC) «Сервер не отвечает» и «Не удалось загрузить задачи».
- Исключено: заголовки, запрещающие встраивание (`curl -I /` — нет `X-Frame-Options` и CSP); отказ во входе
  (был бы экран входа; стартовые запросы Mini App под владельцем отвечают 200 за < 1 с: 33 задачи).
- Найдено в коде и исправлено: `/tasks` и `/subtasks` грузились через `Promise.all`, обрыв любого валил список;
  первая неудача сразу давала уведомление; не было повторов на холодном старте и тайм-аута; опрос мог наложиться.
- Причина конкретного сбоя (холодный старт, деплой или сеть) не подтверждена: нужны логи Render за 10:03 UTC.
  Отказы входа сервер теперь пишет в лог одним словом: «нет заголовка», «подпись неверна», «устарел»,
  «не одобрен», «ключ неверный».
- Скриншот 11:50 «Откройте приложение из Telegram» — сайт открыт обычной ссылкой во встроенном браузере Telegram,
  без initData; это ожидаемое поведение.

## Как проверять изменения (автотестов нет)

- Изоляция пользователей: `python scripts/isolation_check.py` (локально, база в памяти, без сети) — все проверки
  должны проходить. С `--base-url https://…` — HTTP-проверки против живого сервиса на временных пользователях
  (нужны настоящие `SUPABASE_*` и `TELEGRAM_BOT_TOKEN` в `.env`; это запись в прод-базу, только с согласия владельца).
  Скрипту нужны все пакеты из `requirements.txt` (в `venv` владельца нет библиотек Google — ставь отдельное окружение).
- Python: импорт и запуск через `fastapi.testclient.TestClient` с фейковыми переменными окружения.
  Обязательно задай фейковые `SUPABASE_URL`, `SUPABASE_KEY` и `GROQ_API_KEY`: без них `database.py`
  и `groq_client.py` падают ещё при импорте. `SUPABASE_KEY` должен быть похож на JWT (например `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJmb28iOiJiYXIifQ.abc`),
  иначе клиент Supabase откажется стартовать. `TELEGRAM_BOT_TOKEN` в тесте не задавай:
  при старте приложение пойдёт в сеть к Telegram. Маршруты с обращением к базе при фейковом URL падают, это нормально.
- JS: вытащи `<script>` из `web/index.html` и проверь `node --check`. На Mac владельца `node` нет:
  тогда проверяй через `osascript -l JavaScript` (`new Function(src)` выдаёт синтаксические ошибки).
- В локальном `venv` нет библиотек Google, поэтому `import main` там падает. Логику `task_service`
  проверяй на заглушках `google_calendar_service` и `supabase`.
- Интерфейс без настоящей базы: `venv/bin/python design/mock_server.py` поднимает `http://localhost:8001`
  с сайтом и подставными данными в памяти. Запускай его через Bash в фоне, а во встроенном браузере открывай
  конфигурацию `mock` из `.claude/launch.json` (она только подключается к адресу). Сам браузер запустить
  сервер из папки «Загрузки» не может: процесс зависает без доступа к файлам.
- Интерфейс проверяй скриншотами в 390 × 844 и 360 × 740 (плюс ноутбук), без горизонтальной прокрутки,
  и сверяй с макетами в `design/reference/`. Кириллица должна рисоваться Onest и Unbounded.
- Встроенный браузер в скрытой панели ставит таймеры и анимации на паузу: проверки с 5-секундной отменой
  удаления делай быстро или через JS в странице, иначе время истечёт раньше клика.
- Правки большого `index.html` делай скриптом, который проверяет, что каждый якорь вставки встречается
  в файле ровно один раз (неуникальный якорь однажды задвоил кусок файла).

## Статус и планы

Сделано: задачи с датой и временем, теги, подзадачи, заметки, календарь внутри веба, Undo удаления (5 секунд),
голосовой ввод (Telegram через Whisper, веб через Web Speech API), экспорт CSV и печать в PDF,
напоминания 3 раза в день, Google Calendar у каждого свой с честным статусом, новый мобильный дизайн
(все 8 шагов раздела 11 `design/DESIGN.md`): полоса дней, свайп, раскрытые карточки, фильтры, поиск, архив,
заметки, загрузка с подписью про просыпающийся сервер. Несколько пользователей со входом через Telegram Mini App
(см. «Модель доступа»), свои категории у каждого. Всё это в `main` и на проде.

В очереди:
- Утренняя и вечерняя сводка (например команда `/today` и рассылка по расписанию).

  в Xcode не собирались и компилятором не проверялись. Цель iOS 17+.

  календаря при создании задачи (нужна правка разбора на бэкенде).

Не делаем: Telegram Login Widget, роли и права сверх `is_admin`, общие задачи, двустороннюю синхронизацию календаря.
